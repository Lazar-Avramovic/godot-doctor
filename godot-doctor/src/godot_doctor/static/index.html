          Your local second pair of eyes

          Godot Doctor, in your browser

          This workbench uses the same static analyzer as the CLI. It reads selected local project files without launching Godot. Scans never change your source; the automatic fix writes only when you preview and apply it. JSON and text exports include the full report, regardless of filters.

          Launch it from a terminal

          Start Godot Doctor from a terminal in your installed environment. Paste a native Linux or Windows path, or use the folder picker.

          python -m godot_doctor --gui

          Local files. Local session.

          No internet connection, account, or external service is needed. Browsing lists only the folder you request. Source excerpts are restricted to files in the current scan report. Closing this tab does not stop the server; stop it from the launching terminal when finished.

          Automatic fixes are opt-in

          When a config-parse-error is selectable, the inspector can preview a repair. Godot’s ConfigFile treats only ; as a comment, so a # line is folded into the next key and can silently lose a setting. The fix rewrites leading # lines to ; in project.godot. Nothing runs automatically: preview first, then apply. Each previewed line is re-verified before writing.

          What static analysis cannot see

          Importer failures, such as a corrupt or unsupported image, and GDScript compile errors are engine-side. Run godot --headless --import or open the project in the Godot editor to surface them. Binary resources, custom loaders and generated caches stay outside the analyzer.

          What the analyzer checks

          The same diagnostic rules the CLI reports. Select a diagnostic in the workbench to see its remediation.

            Static analysis is not runtime validation

            A clean report means the analyzer found no diagnostics, not that your game is guaranteed to work. Dynamic behavior, engine-specific behavior, and issues outside the analyzer’s rules still need testing in Godot.

            Filesystem compatibility

            Folders that cannot be inspected are marked unavailable. Undecodable Linux filename bytes are displayed as escaped code units; JSON exports preserve them, while text exports show explicit backslash escapes.

            Version information is available when the local server connects.
